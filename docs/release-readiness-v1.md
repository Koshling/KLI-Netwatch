# NETWATCH v1.0 Release Readiness Report

PR #10 готов к ревью и слиянию. База проверки — `5c27970`, коммит слияния PR #9. Среда проверки — Debian 13, Linux/amd64, Go 1.26.10.

## Изменения PR #10

- Список недавних точек глобуса ограничен 512 записями. При переполнении уступает место точка, которая дольше всех находится в списке. Срок жизни точек сохраняется. Регрессионный тест проверяет предел на будущих временных метках и последующее истечение срока.
- При нескольких завершённых установках DB-IP внутри одного каталога Setup выбирает самую свежую работоспособную пару IPv4 и IPv6 по времени изменения файла атрибуции. Проверены пропуск неполной установки, одинаковые времена и сохранение приоритета каталогов и отдельных файлов.
- Историческая заметка теперь описывает действующий предел клиентов. Комментарий классификатора уточняет, что для проверки всплеска нужны 40 запросов за 10 секунд и ответ 403 или 404 на текущий запрос. Правило классификации сохранено.

## Проверки

- `gofmt -l .` не вывел файлов. `go test -count=1 ./...`, `go test -race -count=1 ./...`, `go vet ./...` и `go build -o /tmp/netwatch-test ./cmd/netwatch` прошли. Отдельно собран Linux/amd64 с `CGO_ENABLED=0`. `go list -m all` показал только `netwatch`.
- Setup создал рабочий конфиг из журнала combined и выбрал новую пару NWGEO из двух установок. Для неверного `poll_interval` CLI сообщил имя поля и завершился с кодом 1.
- В псевдотерминале прошли Live по умолчанию без GeoIP, добавление записи, Replay с дисковой NWGEO, окно 15 минут по умолчанию, пауза, ускорение до 100×, перемотка назад и изменения размеров между 60×18, 120×30 и 160×48. После выхода параметры терминала вернулись к исходным. Покрытие Interval, всех парсеров, Traffic Filter и тем входит в тесты репозитория.
- В NWGEO при открытии проверяются диапазоны и строится разреженный индекс. Поиск читает блоки с диска. Проверка дескрипторов показала, что при возврате из Live в меню журнал закрывается. При запуске Replay открывается один дескриптор журнала, а дескриптор NWGEO переиспользуется. Выход по SIGINT восстановил настройки терминала. Тесты также покрывают отмену чтения Replay и ожидание завершения сканирования Interval.

## Память и нагрузка

На одном хосте и одинаковых синтетических данных использован существующий `scripts/profile-netwatch.py` с NWGEO на 262 144 диапазона. В обычном сценарии было 60 000 запросов от 3 000 IP. Пиковый RSS измерял GNU time, живой Go heap взят из последнего поля трассировки GC, с округлением вниз до целых MiB.

| Сценарий с NWGEO | Пиковый RSS до → после | Живой Go heap до → после | CPU до → после |
|---|---:|---:|---:|
| Live, 3 000 IP | 13.9 → 13.6 MiB | 2 → 2 MiB | 0.42 → 0.32 с |
| Replay, 3 000 IP | 13.6 → 13.5 MiB | 2 → 2 MiB | 0.57 → 0.53 с |
| Interval, 3 000 IP | 12.9 → 12.8 MiB | 2 → 2 MiB | 0.19 → 0.23 с |
| Live, 600 000 IP | 47.1 → 47.9 MiB | 19 → 19 MiB | 5.41 → 5.49 с |
| Live, 1 150 IP, 120 секунд | 13.6 → 13.5 MiB | 1 → 1 MiB | 1.98 → 1.98 с |

В нагрузке на 600 000 IP обработаны все 600 000 запросов. Интерфейс показал `65536+`. Это число отражает предел учёта клиентов в одном сеансе, а 600 000 — количество различных адресов во входном журнале. Лента удерживает 100 событий, очередь ожидающих импульсов — до 512, список недавних точек — до 512, активные импульсы — до 12. Кеш GeoIP ограничен 16 384 записями и 4 MiB текста метаданных. [Методика нагрузочных замеров](release-verification.md)

## Оставшиеся ограничения

Терминальный интерфейс считает ширину по рунам. Широкие символы и комбинируемые знаки могут смещать столбцы в отдельных терминалах. Полная обработка ширины отложена на v1.1. Реальная Fedora и боевые журналы в этой среде недоступны. Локальные тесты GeoIP, TLS и установки прошли. Проверку актуального архива DB-IP остановил HTTPS-туннель с кодом 403.
